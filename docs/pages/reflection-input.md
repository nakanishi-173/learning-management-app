# 振り返り入力画面

## 画面の目的

- 1か月分の学習振り返り（学習内容・課題・改善案・メモ）を入力する画面
- 同じ年月で再度登録すると、既存データを更新する

---

## ざっくりまとめ

- 画面表示時：API から既存データは取得しない（空のフォームから入力）
- 保存時：入力チェック → POST → API が DB へ保存（upsert）
- 同じユーザー・同じ年月の振り返りがあれば更新、なければ新規作成

---

## API（`app/api/reflections/route.ts`）

### 全体の流れ（この画面で使う部分）

1. ユーザーが年月と振り返り内容を入力
2. **POST** … 入力内容を検証し、DBへ保存（更新または新規作成）

※ 同ファイルの **GET** は振り返り一覧取得用。`reflection-input` 画面では現状使っていない。

---

### GET（取得）

**用途：** 保存済みの振り返り一覧を取る（他画面などで利用想定）

**DBでの処理：**

1. **振り返りテーブル（`reflection`）**
   - 振り返りを年月の新しい順で取得

**返すもの：**

- 振り返りデータの配列
- 1件もないとき：空配列 `[]`

**失敗時：**

- ステータス 500
- `{ error: "振り返りの取得に失敗しました" }`

---

### POST（保存）

**用途：** フォームの内容を登録・更新する

**受け取るもの：**

- 年（`study_year`）
- 月（`study_month`）
- 主に学習した内容（`study_content`）
- 課題（`challenge`）
- 改善案（`improvement`）
- メモ（`memo`、任意）

**チェック：**

1. 年月・学習内容・課題・改善案が未入力なら 400
2. `{ error: "未入力の項目があります" }` を返す
3. メモは未入力でも OK

**DBでの処理：**

1. **振り返りテーブル（`reflection`）を `upsert`**
   - ユーザーID + 年 + 月 の組み合わせで検索
   - あれば更新、なければ新規作成
   - 保存する内容：学習内容、課題、改善案、メモ

**成功時：**

- `{ message: "登録しました" }`

**失敗時：**

- ステータス 500
- `{ error: "振り返りの保存に失敗しました" }`

---

## 画面の処理

### app/reflection-input/page.tsx

#### 全体の流れ

1. 画面を開く → 空のフォームを表示
2. ユーザーが年月と振り返り内容を入力
3. 「登録」ボタン → 入力チェック → API へ POST

---

#### 定数・型（21〜37行目）

- `start_year` / `end_year` … 年の選択範囲（2026〜2030）
- `years` / `months` … Select用の年・月の選択肢
- `ReflectionInput` … 振り返り入力フォームの型（学習内容・課題・改善案・メモ）

---

#### state（40〜48行目）

画面上の入力値を保持する。

- `year` … 選択中の年
- `month` … 選択中の月
- `form` … 振り返りの入力内容（`studyContent`・`challenge`・`improvement`・`memo`）

---

#### 保存（`handleSaveReflection` / 50〜82行目）

**いつ動く：** 180行目の「登録」ボタン（`onClick={handleSaveReflection}`）

**やること：**

1. 未入力チェック（年月・学習内容・課題・改善案）  
   → 問題あれば `alert` して終了
2. `POST /api/reflections` で送信（DB保存は API 側）
3. 失敗 → API のエラーを `alert`  
   成功 → `alert("登録しました")`

---

#### 画面表示（85〜188行目）

- 入力年月選択（95〜124行目）… 年・月の Select
- 振り返りの入力項目（126〜174行目）
  - 主に学習した内容
  - 課題
  - 改善案
  - メモ（任意）
- 登録ボタン（178〜183行目）… `onClick={handleSaveReflection}`
