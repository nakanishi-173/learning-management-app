# 学習記録入力画面

## 画面の目的

- 日々の学習記録（タスク・学習時間・学習内容・メモ）を入力する画面
- 学習日を変えると、その日の記録を取得して表示する

---

## ざっくりまとめ

- 画面表示時・学習日変更時：GET で指定日の学習記録を取得してフォームへ反映
- 保存時：入力チェック → POST → API が DB へ保存
- 学習記録は upsert、タスクは全削除して再登録

---

## API（`app/api/study-record/route.ts`）

### 全体の流れ

1. **GET** … 指定した学習日の記録を取得してフォームへ表示
2. ユーザーが画面で編集
3. **POST** … 入力内容を検証し、DBへ保存（更新または新規作成）

---

### GET（取得）

**用途：** 画面表示時に、指定した日付の学習記録を取る

**受け取るもの：**

- URL の `study_date`（日付）

**チェック：**

- 日付がなければ 400
- `{ error: "学習日が指定されていません" }`

**DBでの処理：**

1. **学習記録（`studyRecord`）**
   - ユーザーID + 学習日で1件取得
   - 紐づくタスク（`studyTasks`）も一緒に取得（タスクIDの昇順）

**返すもの：**

- **登録済み** … 学習時間、学習内容、メモ、本日のタスク
- **未登録** … 各項目は `null`、タスクは空配列 `[]`

**失敗時：**

- ステータス 500
- `{ error: "学習記録の取得に失敗しました" }`

---

### POST（保存）

**用途：** その日の学習記録を登録・更新する

**受け取るもの：**

- 学習日（`study_date`）
- 学習時間（時・分）
- 学習内容（`subject`）
- メモ（任意）
- 本日のタスク一覧（`study_task`・`is_completed`）

**チェック：**

1. 学習日・学習時間・学習内容・タスク（1件以上）が未入力なら 400
2. `{ error: "未入力の項目があります" }` を返す
3. メモは未入力でも OK
4. 空白だけのタスクは除外してからチェック

**DBでの処理：**

トランザクション（`$transaction`）内で、次の3つをまとめて実行する。途中で失敗したら、すべて取り消す。

1. **学習記録テーブル（`studyRecord`）を `upsert`**
   - ユーザーID + 学習日の組み合わせで検索
   - あれば更新、なければ新規作成
   - 保存する内容：学習時間、学習内容、メモ

2. **タスクテーブル（`studyTask`）の既存データを削除**
   - そのユーザーID・学習日のタスクをすべて `deleteMany`

3. **タスクテーブルへ再登録**
   - 画面から送られたタスクを `createMany` でまとめて登録
   - `study_task_id` は配列の順番（1から）で付与

**成功時：**

- `{ message: "登録しました" }`

**失敗時：**

- ステータス 500
- `{ error: "学習記録の保存に失敗しました" }`

## 画面の処理

### app/study-record-input/page.tsx

#### 全体の流れ

1. 画面を開く → 今日の日付で API から学習記録を取得してフォームへ表示
2. 学習日を変える → その日の記録を再取得
3. ユーザーが入力・編集
4. 「登録」ボタン → 入力チェック → API へ POST

---

#### 型・定数（23〜37行目）

- `Task` … タスク1件（id・text・completed）
- `getTodayString()` … 今日の日付を YYYY-MM-DD 形式で返す

---

#### state（41〜56行目）

画面上の入力値を保持する。

- `hours` / `minutes` … Select用の時・分の選択肢
- `studyDate` … 選択中の学習日（初期値は今日）
- `tasks` … 本日のタスク一覧
- `studyHour` / `studyMinute` … 本日の学習時間
- `subject` … 学習内容
- `memo` … メモ（任意）
- `isSaving` … 保存処理中かどうか（二重送信防止）

---

#### 画面表示時の取得（`useEffect` / 58〜109行目）

**いつ動く：** ページ表示時、および `studyDate` が変わったとき

**やること：**

1. `GET /api/study-record?study_date=...` でデータ取得
2. 失敗したら `console.error` して終了
3. `data.subject` があるかで分岐
   - **登録済み** … 学習時間・内容・メモを state にセット
   - **未登録** … 時間・内容・メモを空にリセット
4. タスクがあれば state に反映、なければ空欄1件を表示
5. 学習日が連続で変わったとき、前のリクエストは `AbortController` でキャンセル
6. 例外が出たら `catch` で `console.error`

---

#### 保存（`handleSaveStudyRecord` / 116〜158行目）

**いつ動く：** 286行目の「登録」ボタン（`onClick={handleSaveStudyRecord}`）

**やること：**

1. 保存中（`isSaving`）なら処理しない
2. タスクに1件以上、有効な入力があるか確認
3. 未入力チェック（学習日・時間・学習内容・タスク）  
   → 問題あれば `alert` して終了
4. 空白だけのタスクを除外して `POST /api/study-record` で送信
5. 失敗 → API のエラーを `alert`  
   成功 → `alert("登録しました")`
6. `finally` で `isSaving` を `false` に戻す

---

#### タスクの操作（111〜114行目）

- `handleAddTask()` … タスク入力欄を1件追加

---

#### 画面表示（160〜293行目）

- 学習日選択（170〜177行目）… date 型の Input
- 本日のタスク（180〜222行目）… チェックボックス・入力欄・追加ボタン
- 本日の学習時間（224〜255行目）… 0〜23時、0〜59分の Select
- 学習内容記入（257〜267行目）… textarea
- メモ（269〜279行目）… 任意入力の textarea
- 登録ボタン（284〜289行目）… `onClick={handleSaveStudyRecord}`
